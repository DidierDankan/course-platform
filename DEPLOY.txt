=====================================================================
  DEPLOY GUIDE: course-platform (Lumen) for free, for a portfolio
=====================================================================

Free plans change often. Before you start, check each service's current free
plan page (limits, sleeping, credit card needed or not).

This file is the deploy procedure. Tasks and their steps live in TODO.txt;
section 2 below only holds the code changes that exist because of this deploy
setup. If TODO.txt and this file disagree, this file wins.


---------------------------------------------------------------------
0. THE PLAN
---------------------------------------------------------------------

  Visitor's browser
        |
        v
  VERCEL  (React client, https://<name>.vercel.app)
        |   /api/*  and  /uploads/*  are forwarded ("rewrites") to Render,
        |   so the browser only ever talks to ONE domain -> login cookies work
        v
  RENDER  (Express server, https://<name>.onrender.com)
        |                         |
        v                         v
  AIVEN (MySQL database)    SUPABASE STORAGE (images + videos)

  STRIPE (test mode) sends the payment webhook straight to Render.

Why not everything on Vercel?
  Vercel runs a backend as short-lived functions: no permanent disk (your
  uploads/ folder would vanish), small request size limits (no video uploads)
  and Stripe webhooks are harder. A normal always-on server (Render) fits Express.

Why the "rewrites" trick?
  If the client is on vercel.app and the API on onrender.com, they are two
  different sites. Browsers block or don't send cookies between different sites,
  so login would break. Forwarding /api through Vercel makes it one site.

2.1 Database connection: port + SSL  (server/db/connection.js)
    Aiven gives you a host, a port (NOT 3306) and requires SSL.
    1. add to createPool:
         port: Number(process.env.DB_PORT) || 3306,
         ssl: process.env.DB_SSL === "true" ? { rejectUnauthorized: true, ca: process.env.DB_CA_CERT } : undefined,
    2. locally leave DB_SSL unset, so WAMP keeps working
    3. on Render you will set DB_SSL=true and paste Aiven's CA certificate into DB_CA_CERT

2.2 Uploads: disk -> Supabase Storage  (the biggest change)
    Render's free plan has no permanent disk: files saved to uploads/ are
    deleted on every restart/deploy. So files must live in Supabase.
    1. Supabase -> Storage -> create TWO buckets:
         "public-media"  (Public)   -> thumbnails and profile photos
         "course-videos" (Private)  -> lesson videos
    2. server: npm install @supabase/supabase-js
    3. new file server/lib/storage.js: create the Supabase client with
       SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY (server only, never in the client)
    4. uploadMiddleware.js: switch multer to memoryStorage() and lower
       MAX_FILE_SIZE_MB to 50 (Supabase free per-file limit, and Render has little memory)
    5. where files are saved (CourseService insertCourseMedia/insertCourseVideos,
       profile update): upload the buffer to the right bucket with the same
       uuid + extension name, and store the bucket path in the url column
       (e.g. "videos/<uuid>.mp4", "images/<uuid>.png")
    6. images: return the bucket's public URL to the client
    7. videos: keep protectVideos.js as the gate. After the same owner/admin/
       enrolled/preview check, answer with a redirect (302) to a short-lived
       signed URL: createSignedUrl(path, SIGNED_URL_TTL_SECONDS), e.g. 15 min
       trade-off: whoever holds the link can watch until it expires, so keep it
       short; if playback errors after expiry, the watch page reloads the video
       src at the same position (production version: HLS streaming with
       per-segment tokens, or a CDN with signed cookies)
    8. deletes (deleteMediaByIdWithFile, deleteAllCourseMedia, old profile image):
       remove the object from the bucket instead of fs.unlink
    9. test locally: create a course, watch as buyer, delete it, check the bucket

2.3 JWT secrets

2.4 API address for the live build

2.5 Vercel config  (new file client/vercel.json)
    {
      "rewrites": [
        { "source": "/api/:path*",     "destination": "https://<your-render-name>.onrender.com/api/:path*" },
        { "source": "/uploads/:path*", "destination": "https://<your-render-name>.onrender.com/uploads/:path*" },
        { "source": "/(.*)",           "destination": "/index.html" }
      ]
    }
    The last rule makes React Router pages (/courses/10, /user/dashboard)
    work when someone opens or refreshes them directly.
    Fill in the Render name after step 4.

---------------------------------------------------------------------
3. DATABASE ON AIVEN
---------------------------------------------------------------------
1. Aiven -> Create service -> MySQL -> Free plan -> pick a region near you (Europe)
2. wait until it is "Running", then open it and note:
     host, port, user (avnadmin), password, database name (defaultdb)
   and download the CA certificate (ca.pem)
3. export your local database (Git Bash, project folder):
     /c/wamp64/bin/mysql/mysql9.1.0/bin/mysqldump.exe -u root -p \
       --no-tablespaces --set-gtid-purged=OFF --routines \
       course_platform > course_platform.sql
   (delete the e2e test users/courses first, or start from the migrations /
    schema.sql and create clean demo data instead. Don't use schema.sql until
    the TODO.txt fix is done: today it fails on a fresh database)
4. import it into Aiven:
     /c/wamp64/bin/mysql/mysql9.1.0/bin/mysql.exe -h <host> -P <port> -u avnadmin -p \
       --ssl-mode=REQUIRED defaultdb < course_platform.sql
5. check: connect the same way and run  SHOW TABLES;
6. do NOT commit course_platform.sql (it contains password hashes); add it to .gitignore

Note: free databases can be paused/powered off after a period of no use.
Read Aiven's free plan terms and restart it from the console if that happens.


---------------------------------------------------------------------
4. SERVER ON RENDER
---------------------------------------------------------------------
1. Render -> New -> Web Service -> connect the GitHub repo
2. settings:
     Root Directory:  server
     Runtime:         Node
     Build Command:   npm install
     Start Command:   node index.js
     Instance type:   Free
3. Environment variables (Render -> Environment):
     NODE_ENV=production
     DB_HOST=<aiven host>
     DB_PORT=<aiven port>
     DB_USER=avnadmin
     DB_PASS=<aiven password>
     DB_NAME=defaultdb
     DB_SSL=true
     DB_CA_CERT=<paste the whole ca.pem content>
     JWT_ACCESS_SECRET=<long random string, see below>
     JWT_REFRESH_SECRET=<a different long random string>
     STRIPE_SECRET_KEY=sk_test_...        (test key only)
     STRIPE_WEBHOOK_SECRET=<from step 6, fill in later>
     CLIENT_URL=https://<your-name>.vercel.app
     SUPABASE_URL=<from Supabase -> Project Settings -> API>
     SUPABASE_SERVICE_ROLE_KEY=<same page, service_role key>
     SIGNED_URL_TTL_SECONDS=900
   Make each JWT secret (run twice, use different values):
     node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
   Render sets PORT by itself; index.js already reads process.env.PORT.
4. Deploy, then open https://<name>.onrender.com/  -> should say "Server is running!"
5. check the Render logs for "Connected to database"

Note: the free plan sleeps after ~15 minutes without visitors. The first
visit after that takes up to about a minute. Mention it on your portfolio
("first load may take a minute, free hosting").


---------------------------------------------------------------------
5. CLIENT ON VERCEL
---------------------------------------------------------------------
1. put your Render address into client/vercel.json (step 2.5), commit, push
2. Vercel -> Add New -> Project -> import the GitHub repo
3. settings:
     Root Directory:    client
     Framework Preset:  Vite
     Build Command:     npm run build
     Output Directory:  dist
4. Environment variables: none needed (client/.env.production is in the repo)
   Never put secret keys in VITE_ variables: they end up in the browser.
5. Deploy, then open https://<name>.vercel.app
6. if you chose a different Vercel name, update CLIENT_URL on Render and redeploy it

Note: if large video uploads fail through Vercel's forwarding (request size
limits), upload your demo course videos while testing locally against the
live database/storage, or keep demo videos small. Check Vercel's current
limits for rewrites to external URLs.


---------------------------------------------------------------------
6. STRIPE WEBHOOK (test mode)
---------------------------------------------------------------------
1. Stripe dashboard, TEST mode -> Developers -> Webhooks -> Add endpoint
2. URL:    https://<name>.onrender.com/api/payments/webhook
   (straight to Render, not through Vercel: Stripe's signature check needs the raw request)
3. event:  checkout.session.completed
4. copy the endpoint's "Signing secret" (whsec_...) into STRIPE_WEBHOOK_SECRET on Render, redeploy
   (it is different from the one `stripe listen` prints locally)

9. LIMITS OF THE FREE SETUP (good to know, fine for a portfolio)
---------------------------------------------------------------------
  - Render free sleeps after inactivity (slow first load)
  - free database and storage have small limits (keep demo videos short)
  - free plans can pause unused projects (Supabase pauses inactive free projects;
    check Aiven's terms too): open the site now and then, or restart from the console
  - Stripe stays in test mode; real payments would need a verified Stripe account
